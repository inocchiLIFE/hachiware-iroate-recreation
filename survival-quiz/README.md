# 2択サバイバルクイズ

150人規模のイベント向けの、スマホで参加する「2択サバイバルクイズ」Webアプリです。
司会者が1問ずつ出題し、全員が同時に A / B で回答。間違えた人・時間内に答えなかった人は脱落し、最後まで残った人が勝者です。

- 構成：**Next.js 16（App Router）+ Firebase Cloud Firestore**、公開先は **Vercel**
- 費用：**すべて無料枠内**で動く設計です（Firebase は無料の Spark プラン、Vercel は無料の Hobby プラン）。詳しくは「[費用と無料枠](#費用と無料枠)」を参照してください。

## 画面

| URL | 用途 |
| --- | --- |
| `/` | 参加者画面（スマホ）。ニックネーム登録 → 待機 → 出題・回答 → 結果 |
| `/screen` | スクリーン表示（プロジェクター・横長）。QRコード・問題・カウントダウン・集計・勝者 |
| `/admin` | 管理画面（パスワード保護）。進行操作・問題の登録/CSVインポート・参加者管理・リセット |

## ルール（実装済みの仕様）

- 制限時間は **10秒**（管理画面で3〜120秒に変更可）。
- 締め切りの判定は**サーバー時刻**。サーバーが回答を受け取った時刻が「締め切り＋猶予」を過ぎていれば無効。
  - 猶予（既定 500ms）は「0秒直前に押した回答が通信中に締め切りを過ぎる」ケースの救済用です。画面のカウントダウンは猶予なしで0になり、ボタンも押せなくなります。厳密にしたい場合は管理画面で 0 にできます。
- 回答の変更は**不可**（サーバーで1人1問1回答を強制。通信リトライによる同じ回答の再送は重複扱い）。
- 全員が脱落する問題では、**その問題での脱落をなかったことにして全員復活**。
- 最後に複数人が残った場合は、**累計の回答時間が短い順**に順位をつけます（正解した問題の回答時間の合計。全員復活した問題は回答時間、未回答なら制限時間ぶんを加算）。
- **1問目の出題後は新規参加不可**（出題前でも管理画面で受付を締め切れます）。
- 脱落後は観戦モード。問題と結果を見続けられ、**参考回答**もできます（判定・集計には影響しません。管理画面でオフにできます）。
- 出題ボタンを押すと、**1.5秒後に全端末で同時に**問題が表示されます（端末ごとの通信差で不公平にならないよう、表示開始時刻もサーバー時刻で揃えています）。回答時間はこの表示開始時刻から計測します。

## 仕組み

```
 参加者スマホ ×150 ─┐  読み取り（リアルタイム購読）       ┌─ Cloud Firestore
 スクリーン         ├──────────────────────────────────▶│   game/state       … 進行状態（1ドキュメント）
 管理画面           │                                    │   participants/{id} … 生存/脱落・累計回答時間
                    │  書き込みは API 経由のみ            │   answers/{q}_{id}  … 回答（create のみ）
                    └──▶ Vercel（Next.js API ルート）───▶│   questions / secrets / nicknames … 非公開
                         Firebase Admin SDK              └─ セキュリティルールでブラウザからの書き込みは全面禁止
```

- **状態の配信**：全端末が `game/state` 1ドキュメントを Firestore でリアルタイム購読。出題・締め切り・正解発表は、このドキュメントを1回書き換えるだけで全端末に届きます（エミュレーターでの150台試験では反映遅延 p95 で約0.2秒）。
- **回答の受付**：`POST /api/answer`。サーバーが受信時刻で締め切りを判定し、`answers/{問題}_{参加者}` を `create`（既存なら失敗）で作るため、回答の変更は仕組み上できません。
- **脱落判定**：正解発表のときにサーバーが一括判定し、参加者とゲーム状態を1つのバッチで原子的に更新します。
- **再接続**：Firestore SDK が自動で再接続し、最新状態に追いつきます。加えて、スリープ復帰・オンライン復帰・キャッシュ表示の継続を検知すると接続を張り直します。参加者IDとトークン、自分の回答は端末（localStorage）に保存されるので、リロードしても同じ参加者として復帰します（脱落状態はサーバー側で保持）。
- **管理者認証**：`ADMIN_PASSWORD` でログインし、署名付きの HttpOnly Cookie（12時間有効）で管理 API を保護します。

## 費用と無料枠

| サービス | プラン | 備考 |
| --- | --- | --- |
| Firebase（Cloud Firestore） | **Spark（無料）** | クレジットカード登録不要。Cloud Functions・Authentication・Hosting は使いません |
| Vercel | **Hobby（無料）** | 個人・非商用の利用に限られます。`*.vercel.app` のドメインをそのまま使います |

Firestore の無料枠は **1日あたり読み取り 5万回・書き込み 2万回・削除 2万回**です（太平洋時間の0時、日本時間では夏は16時・冬は17時にリセット）。上限を超えると課金はされずに、その日は読み書きが失敗するようになります（Spark プランの場合）。

150人・20問の本番1回の目安（概算）：

| 項目 | 目安 |
| --- | --- |
| 読み取り | 約2〜2.5万回（1問あたり約1,000回 ＋ 参加登録・接続時の読み込み） |
| 書き込み | 約6,500回（1問あたり約300回 ＋ 参加登録） |
| 削除 | 約3,500回（リセット1回あたり） |

読み取りを抑えるため、次のように設計しています。

- 判定中の状態など、表示に不要な変化は `game/state` に書かない
- スクリーンと管理画面の「回答済み人数」は、回答を全件購読するのではなく、集計クエリ（count。1,000件まで読み取り1回分）を1秒ごとに取得する
- 自分の回答は Firestore を購読せず、端末に保存する
- 参加者一覧の購読は、スクリーンでは受付中だけ、管理画面では参加者タブを開いている間だけにする

> ⚠ **負荷テストは本番と同じ日に何度も回さないでください。** 150体×5問のテストで、読み取り約5,000回・書き込み約2,000回を使います。本番の Firebase プロジェクトとは別に、**負荷テスト・リハーサル用の Firebase プロジェクト（これも無料）**を作るのがおすすめです（[docs/LOAD_TEST.md](docs/LOAD_TEST.md)）。

## ローカルで試す（エミュレーター・Firebase アカウント不要）

Node.js 22 以上と Java 11 以上が必要です（Java は Firestore エミュレーター用）。

```bash
cd survival-quiz
npm install
cp .env.emulator .env.local
npm run emulators        # ターミナル1：Firestore エミュレーター（http://127.0.0.1:4000 で中身を確認できます）
npm run dev              # ターミナル2：http://localhost:3000
```

管理画面 http://localhost:3000/admin のパスワードは `admin` です（`.env.emulator` で設定）。
