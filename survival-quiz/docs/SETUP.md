# セットアップから公開までの手順書

所要時間の目安：30〜45分。**すべて無料プランで完結し、クレジットカードの登録は不要です。**
途中で「アップグレード」「Blaze プラン」「有料」などの案内が出ても、選ばずに進めてください。

> Firebase コンソールや Vercel の画面の文言・配置は変わることがあります。見つからない場合は、近い名前のメニューを探してください。

---

## 0. 必要なもの

- Google アカウント（Firebase 用）
- GitHub アカウント（このリポジトリにアクセスできるもの）
- Vercel アカウント（GitHub アカウントでサインアップできます。Hobby＝無料プラン）
- ローカルで試す・負荷テストをする場合：Node.js 22 以上（エミュレーターを使う場合は Java 11 以上も）

---

## 1. Firebase プロジェクトを作る

1. https://console.firebase.google.com/ を開き、「プロジェクトを作成（プロジェクトを追加）」を選びます。
2. プロジェクト名を入力します（例：`survival-quiz`）。表示される **プロジェクト ID** を控えておきます。
3. Google アナリティクスは**無効**で構いません。
4. 作成後、左下などに表示されるプランが **Spark（無料）** になっていることを確認します。**アップグレードはしないでください。**

> 負荷テスト・リハーサル用に、同じ手順でもう1つ別のプロジェクト（例：`survival-quiz-test`）を作っておくと、本番用の無料枠を消費せずに済みます（[LOAD_TEST.md](LOAD_TEST.md)）。

## 2. Cloud Firestore を作成する

1. 左メニューの「構築（Build）」→「Firestore Database」→「データベースを作成」。
2. データベース ID は **`(default)` のまま**にします（無料枠は `(default)` データベースにだけ適用されます）。
3. ロケーションは **`asia-northeast1`（東京）** か **`asia-northeast2`（大阪）** を選びます。**後から変更できません。** 選んだ場所に合わせて、`vercel.json` の `regions` を東京なら `hnd1`、大阪なら `kix1` にします（このリポジトリは大阪 `kix1` に設定済み）。
4. セキュリティルールは「**本番環境モード**」で開始します（次の手順で正式なルールに置き換えます）。

## 3. セキュリティルールとインデックスを設定する

ブラウザからは読み取りだけを許可し、書き込みはすべてサーバー（API）経由に限定するルールです。
**方法 A（コンソールで貼り付け）**と**方法 B（CLI）**のどちらかで設定します。

### 方法 A：コンソールで設定

1. Firestore Database の「ルール」タブを開きます。
2. エディタの中身を、このリポジトリの `survival-quiz/firestore.rules` の内容で丸ごと置き換え、「公開」を押します。
3. 「インデックス」タブ →「複合」→「インデックスを作成」で、次の内容を作成します。
   - コレクション ID：`answers`
   - フィールド 1：`q`（昇順）
   - フィールド 2：`spectator`（昇順）
   - クエリのスコープ：コレクション
   - 作成には数分かかります。状態が「有効」になれば完了です。

### 方法 B：CLI で設定

```bash
cd survival-quiz
npm install
npx firebase login
npx firebase deploy --only firestore --project <プロジェクトID>
```

`firestore.rules` と `firestore.indexes.json` がまとめて反映されます。

## 4. ウェブアプリを登録する（ブラウザ用の設定値）

1. 「プロジェクトの概要」の横の歯車 →「プロジェクトの設定」→「全般」タブ。
2. 「マイアプリ」で **ウェブ（`</>`）** アイコンを押し、アプリのニックネームを入力して登録します。**「Firebase Hosting も設定する」にはチェックを入れません。**
3. 表示される `firebaseConfig` の値を控えます。

| firebaseConfig | 環境変数 |
| --- | --- |
| `apiKey` | `NEXT_PUBLIC_FIREBASE_API_KEY` |
| `authDomain` | `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN` |
| `projectId` | `NEXT_PUBLIC_FIREBASE_PROJECT_ID` |
| `appId` | `NEXT_PUBLIC_FIREBASE_APP_ID` |

> これらはブラウザに配信される公開情報です（秘密ではありません）。データの保護はセキュリティルールで行っています。

## 5. サービスアカウントの秘密鍵を作る（サーバー用）

1. 「プロジェクトの設定」→「サービス アカウント」タブ。
2. 「Firebase Admin SDK」で「**新しい秘密鍵を生成**」を押し、JSON ファイルをダウンロードします。
3. JSON の中の値を控えます。

| JSON のキー | 環境変数 |
| --- | --- |
| `project_id` | `FIREBASE_PROJECT_ID` |
| `client_email` | `FIREBASE_CLIENT_EMAIL` |
| `private_key` | `FIREBASE_PRIVATE_KEY` |

> ⚠ この JSON は**データベースを自由に読み書きできる鍵**です。Git にコミットしたり、チャットやメールで送ったりしないでください。不要になったら同じ画面から鍵を削除できます。

Authentication（ログイン機能）や Cloud Functions、Storage の設定は**不要**です。

## 6. ローカルで動作確認する（任意・推奨）

```bash
cd survival-quiz
npm install
cp .env.example .env.local
# .env.local を開いて、手順4・5の値と ADMIN_PASSWORD を記入
npm run dev
```

- http://localhost:3000/admin を開き、パスワードでログインできれば Firebase との接続は成功です。
- `FIREBASE_PRIVATE_KEY` は、JSON の `private_key` の値（`-----BEGIN PRIVATE KEY-----\n...`）を**ダブルクォートで囲んで** `\n` のまま1行で貼り付けます。

Firebase を使わずに試したい場合は、エミュレーターで動かせます（README の「ローカルで試す」を参照）。

## 7. Vercel に公開する

1. https://vercel.com/ に GitHub アカウントでログインします。プランは **Hobby（無料）** を選びます。
2. 「Add New…」→「Project」→ このリポジトリ（`hachiware-iroate-recreation`）を「Import」します。
   - GitHub 連携の権限確認が出たら、このリポジトリへのアクセスを許可します。
3. 設定画面で次のように指定します。
   - **Root Directory**：`survival-quiz`（「Edit」を押して選択。**必須**です。リポジトリ直下の別サイトとは独立しています）
   - Framework Preset：Next.js（自動で選ばれます）
   - Build Command・Output Directory：変更不要
4. 「Environment Variables」に次をすべて登録します。

   | 名前 | 値 |
   | --- | --- |
   | `NEXT_PUBLIC_FIREBASE_API_KEY` | 手順4 |
   | `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN` | 手順4 |
   | `NEXT_PUBLIC_FIREBASE_PROJECT_ID` | 手順4 |
   | `NEXT_PUBLIC_FIREBASE_APP_ID` | 手順4 |
   | `FIREBASE_PROJECT_ID` | 手順5 |
   | `FIREBASE_CLIENT_EMAIL` | 手順5 |
   | `FIREBASE_PRIVATE_KEY` | 手順5（`-----BEGIN PRIVATE KEY-----` から `-----END PRIVATE KEY-----\n` まで。両端のダブルクォートは不要） |
   | （かんたんな方法）`FIREBASE_SERVICE_ACCOUNT` | 上の `FIREBASE_CLIENT_EMAIL`・`FIREBASE_PRIVATE_KEY` の代わりに、手順5でダウンロードした JSON ファイルを「メモ帳」などで開き、**中身をすべて**貼り付けても動きます |
   | `ADMIN_PASSWORD` | 管理画面のパスワード（推測されにくい長いもの） |
   | `ADMIN_SESSION_SECRET` | 任意。長いランダム文字列（未設定でも動きます） |
   | `NEXT_PUBLIC_JOIN_URL` | 任意。QRコードに載せる URL（未設定ならスクリーンを開いているドメイン） |

   **`FIRESTORE_EMULATOR_HOST` と `NEXT_PUBLIC_FIRESTORE_EMULATOR_HOST` は登録しないでください**（登録するとエミュレーターに接続しようとして動きません）。

5. 「Deploy」を押します。1〜2分で `https://<プロジェクト名>.vercel.app` が発行されます。
6. サーバーの実行リージョンは `vercel.json` で **大阪（kix1）** に設定済みです（Firestore と同じ場所で動かすと遅延が小さくなります。Firestore を東京にした場合は `hnd1` に変更してください）。

> 環境変数を後から変更した場合は、Vercel の「Deployments」から最新のデプロイを「Redeploy」してください（特に `NEXT_PUBLIC_` で始まる変数はビルド時に埋め込まれます）。
>
> 独自ドメインは不要です（ドメインの取得には費用がかかるため、`*.vercel.app` のまま使う想定です）。

## 8. 公開後の確認

1. `https://<あなたのURL>/admin` にログインします。
2. 「問題」タブで問題を登録し、「保存」します。
   - CSV でインポートする場合は「CSV ファイルを選ぶ」を押します。形式は `問題文,選択肢A,選択肢B,正解(A/B)`（UTF-8。Excel では「CSV UTF-8」で保存）。`sample-questions.csv` が見本です。
3. 別の端末で `/screen` を開くと QR コードが表示されます。スマホで読み取って参加し、管理画面から一通り進行してみます。
4. 確認が終わったら「設定・リセット」→「ゲームをリセット」で参加者を消去します（問題は残ります）。
5. 本番前に一度、負荷テストを実施してください（[LOAD_TEST.md](LOAD_TEST.md)）。

## 当日の運用

### 準備（開始30分前まで）

- [ ] 管理画面で問題と正解を最終確認する（「次の問題」欄に正解が表示されます）
- [ ] 「設定・リセット」で制限時間（10秒）・猶予・選び直しの可否・観戦者の参考回答を確認する
- [ ] **「ゲームをリセット」**を実行する（リハーサルの参加者を消すため）
- [ ] プロジェクター用 PC で `/screen` を開き、ブラウザを全画面（F11 / macOS は ⌃⌘F）にする
- [ ] スクリーン右下の「🔇 クリックで音を出す」を押し、会場のスピーカーから音が出るか確認する（ページを開き直すたびに押し直しが必要です）
- [ ] 司会者用の PC（またはタブレット）で `/admin` を開く。**管理画面は1つの端末だけで開いておく**のがおすすめです

### 進行

管理画面の上部のボタンを順に押します。次に押すべきボタンはオレンジの枠で強調されます。

1. **参加受付の締め切り**（任意。押さなくても1問目の出題で自動的に締め切られます）
2. **出題** → 1.5秒後に全端末で問題が表示され、10秒のカウントダウン開始
3. **回答締め切り** → 制限時間が過ぎると**管理画面が自動で実行**します（早めに締め切りたいときだけ手動で押します）
4. **正解発表** → 脱落判定。スクリーンに A/B の人数・正解・生存者数が出ます
5. **次の問題へ** → 「まもなく出題」表示 → 2 に戻る
6. 生存者が1人になった、または問題がなくなったら **終了・勝者発表**

- 全員が不正解だった問題は、自動で「全員復活」になります。
- 参加者タブで、特定の参加者を**復活**・**脱落させる**・**退場**（不適切なニックネームの削除など）ができます。
- 管理画面を誤って閉じても、開き直せば続きから操作できます（状態はすべて Firestore にあります）。

### 参加者からのよくある質問

- **画面が固まった・止まった** → ページを再読み込みしてください。同じ参加者として復帰します（回答済み・脱落の状態も維持されます）。
- **「参加受付は終了しました」と出る** → 1問目の出題後は新規参加できません。
- **別のブラウザやシークレットモードで開いた** → 参加情報は端末のブラウザごとに保存されるため、最初に参加したブラウザで開き直してください。

### 会場のネットワーク

- 150台が同時に使う会場 Wi-Fi は混雑しやすいので、**モバイル回線（4G/5G）での参加も案内**しておくと安心です。
- アプリは通信が切れても自動で再接続しますが、切れている間に締め切られた問題は「時間切れ」になります。

## トラブルシューティング

| 症状 | 確認すること |
| --- | --- |
| 管理画面で「サーバーエラー」 | Vercel の環境変数（特に `FIREBASE_PRIVATE_KEY`）。Vercel の「Logs」にエラー内容が出ます |
| 画面が「接続中…」のまま | `NEXT_PUBLIC_FIREBASE_*` の値・Firestore のルールが公開されているか。変更後は Redeploy |
| スクリーンの「回答済み」が「–」のまま | 手順3の複合インデックス（answers: q, spectator）が「有効」になっているか |
| 途中から読み書きが失敗する | Firestore の無料枠（1日あたりの上限）を超えた可能性。Firebase コンソールの「使用量」で確認。日本時間の16時（冬は17時）にリセットされます |
| QR コードの URL が違う | `NEXT_PUBLIC_JOIN_URL` を設定して Redeploy |
